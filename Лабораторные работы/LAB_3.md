# Лабораторная работа №3 "Поиск ArUco-маркера в заданной области с оптимизацией высоты полёта"

## Описание проекта

Проект посвящён моделированию автономного поиска визуальной метки ArUco беспилотным летательным аппаратом в пределах заданной прямоугольной области. Основная задача заключается в выборе оптимальной высоты полёта и стратегии облёта области для гарантированного обнаружения метки за минимальное время.

Высота полёта влияет на два противоположных по характеру параметра. С увеличением высоты возрастает площадь поверхности, попадающая в поле зрения камеры, что сокращает количество проходов и общее время облёта. Однако одновременно уменьшается размер маркера в пикселях изображения, и при достижении нижнего порога распознаваемости детектор ArUco перестаёт надёжно обнаруживать метку. Студенту необходимо рассчитать максимально допустимую высоту, при которой проекция маркера на матрицу камеры остаётся не меньше минимально необходимого размера в пикселях.

На основании рассчитанной высоты определяется ширина зоны охвата камеры. Затем строится траектория облёта области по типу «змейка» (boustrophedon), обеспечивающая полное покрытие при заданном перекрытии соседних проходов. По итогам моделирования измеряется фактическое время поиска и оценивается надёжность обнаружения метки.

## Цель проекта

Разработать алгоритм автономного поиска ArUco-маркера в заданной прямоугольной области с расчётом оптимальной высоты полёта на основе параметров камеры и размера маркера, и реализовать его в среде Gazebo с минимизацией общего времени выполнения миссии.

## Основная идея

Эффективность поиска маркера зависит от соотношения трёх величин: высоты полёта, размера маркера и разрешающей способности камеры. На малой высоте площадь покрытия мала, и для облёта всей области требуется большое количество проходов. На большой высоте площадь покрытия велика, но проекция маркера на матрицу камеры становится слишком малой для надёжного распознавания.

Существует предельная высота `h_max`, при которой размер маркера в пикселях изображения равен минимально допустимому значению для устойчивой работы детектора ArUco. Полёт ниже этой высоты гарантирует обнаружение, но увеличивает время миссии. Полёт выше — сокращает количество проходов, но приводит к пропуску метки.

Оптимальной является высота, незначительно меньшая `h_max`. На её основе вычисляется ширина зоны охвата, выбирается шаг между параллельными проходами с учётом перекрытия, и строится маршрут типа «змейка», обеспечивающий полное покрытие области.

Поскольку положение маркера в пределах области поиска задаётся случайным образом, фактическое время до его обнаружения существенно варьируется от запуска к запуску. Для получения устойчивой оценки качества алгоритма миссия выполняется многократно, а итоговый показатель определяется как усреднённое значение по серии запусков.

## Расчёт оптимальной высоты полёта

Зона охвата камеры на поверхности земли при высоте полёта `h` определяется углами обзора:

```text
W_ground = 2 * h * tan(FOV_h / 2)
H_ground = 2 * h * tan(FOV_v / 2)
```

где:

- `W_ground` — ширина зоны охвата на поверхности по горизонтали, м;
- `H_ground` — высота зоны охвата на поверхности по вертикали, м;
- `FOV_h, FOV_v` — горизонтальный и вертикальный углы обзора камеры.

Размер одного пикселя на поверхности (Ground Sample Distance):

```text
GSD = W_ground / W = (2 * h * tan(FOV_h / 2)) / W
```

Размер маркера в пикселях изображения:

```text
p_marker = s / GSD = (s * W) / (2 * h * tan(FOV_h / 2))
```

Из условия `p_marker ≥ p_min` следует ограничение на максимальную высоту:

```text
h_max = (s * W) / (2 * p_min * tan(FOV_h / 2))
```

Подстановка значений из условия задачи:

```text
h_max = (0.5 * 640) / (2 * 30 * tan(40°))
h_max = 320 / (60 * 0.839)
h_max = 320 / 50.34
h_max ≈ 6.36 м
```

В качестве рабочей высоты следует выбирать значение, незначительно меньшее `h_max`, для обеспечения запаса по надёжности детектирования. Например:

```text
h_work = 0.9 * h_max ≈ 5.7 м
```

## Расчёт траектории облёта

При высоте `h_work` зона охвата камеры составит:

```text
W_ground = 2 * 5.7 * tan(40°) ≈ 9.57 м
H_ground = 2 * 5.7 * tan(32°) ≈ 7.12 м
```

Для гарантированного покрытия области используется перекрытие соседних проходов на величину `overlap`. Рекомендуемое значение:

```text
overlap = 0.2
```

Шаг между параллельными проходами:

```text
d_step = W_ground * (1 - overlap)
d_step = 9.57 * 0.8 ≈ 7.66 м
```

Количество параллельных проходов для области шириной `L_x`:

```text
N_passes = ceil(L_x / d_step)
N_passes = ceil(30 / 7.66) = 4
```

Длина одного прохода равна длине области по оси Y:

```text
L_pass = L_y = 30 м
```

Суммарная длина горизонтальных перелётов:

```text
L_horizontal = N_passes * L_pass = 4 * 30 = 120 м
```

Суммарная длина боковых смещений между проходами:

```text
L_lateral = (N_passes - 1) * d_step = 3 * 7.66 ≈ 23 м
```

Полная длина маршрута:

```text
L_total = L_horizontal + L_lateral ≈ 143 м
```

## Модель времени выполнения миссии

Общее время миссии складывается из времени взлёта, полёта по маршруту и посадки:

```text
T_total = T_takeoff + T_flight + T_landing
```

Время полёта при заданной скорости:

```text
T_flight = L_total / v
T_flight = 143 / 3 ≈ 47.7 с
```

Полное время миссии:

```text
T_total = 5 + 47.7 + 5 ≈ 57.7 с
```

Если в процессе полёта маркер обнаружен раньше завершения маршрута, миссия может быть прекращена досрочно. В этом случае фиксируется время до момента обнаружения.

## Усреднение результатов по серии запусков

Поскольку положение маркера в пределах области поиска задаётся случайным образом, время до его обнаружения зависит от расположения маркера относительно начальной точки маршрута. В случае, когда маркер находится в начале траектории облёта, миссия завершается быстро. Если маркер расположен в конце маршрута, время поиска приближается к полному времени облёта области.

Для получения устойчивой и репрезентативной оценки качества разработанного алгоритма миссия выполняется многократно. Положение маркера на каждом запуске формируется заново случайным образом в пределах заданной области. Итоговое время определяется как среднее арифметическое по серии запусков:

```text
T_avg = (1 / N) * Σ T_i
```

где:

- `T_avg` — усреднённое время выполнения миссии;
- `N` — количество запусков (рекомендуется N = 10);
- `T_i` — время выполнения i-го запуска миссии.

Дополнительно вычисляется среднеквадратичное отклонение времени для оценки стабильности результатов:

```text
σ_T = sqrt((1 / N) * Σ(T_i - T_avg)^2)
```

Аналогичным образом усредняется эталонное время `T_optimal_avg`, полученное преподавателем при использовании оптимального алгоритма на той же серии случайных положений маркера.

## Алгоритм работы

Рекомендуемая последовательность действий программы.

### Этап 1. Расчёт параметров полёта

На основе характеристик камеры и размера маркера вычисляется максимально допустимая высота `h_max`. Выбирается рабочая высота `h_work` с запасом по надёжности. Рассчитывается ширина зоны охвата и шаг между проходами.

### Этап 2. Построение маршрута

Формируется список waypoint-точек, образующих маршрут типа «змейка» в пределах заданной области. Точки задаются в системе координат полигона с учётом высоты `h_work`.

### Этап 3. Выполнение миссии

Квадрокоптер выполняет взлёт на рабочую высоту, последовательно проходит точки маршрута. На каждом кадре изображения с камеры выполняется поиск ArUco-маркера средствами библиотеки OpenCV.

### Этап 4. Обработка обнаружения

При обнаружении маркера фиксируются: его идентификатор, координаты квадрокоптера в момент обнаружения, время с начала миссии. Полёт может быть остановлен или продолжен до завершения маршрута в зависимости от выбранной стратегии.

### Этап 5. Завершение миссии

После завершения маршрута или досрочного обнаружения маркера квадрокоптер возвращается в стартовую точку и выполняет посадку.

## Метрики оценки

Для количественной оценки качества работы алгоритма используются следующие метрики.

### Время до обнаружения маркера

```text
T_detect = t_marker_found - t_mission_start
```

### Общее время миссии

```text
T_total = T_takeoff + T_flight + T_landing
```

### Отклонение времени от эталона

```text
δT = T_avg / T_optimal_avg
```

где:

- `T_avg` — усреднённое время по серии запусков, выполненных студентом;
- `T_optimal_avg` — усреднённое эталонное время по той же серии случайных положений маркера, полученное преподавателем.

### Размер маркера в пикселях при обнаружении

```text
p_detected = (s * W) / (2 * h_actual * tan(FOV_h / 2))
```

Условие надёжности обнаружения:

```text
p_detected ≥ p_min
```

### Площадь покрытой области

```text
S_covered = N_passes * d_step * L_pass
```

### Коэффициент эффективности покрытия

```text
η = S_target / L_total
```

где `S_target` — площадь заданной области (900 м² при 30 × 30 м).

## Критерии оценивания

Основным критерием оценивания результатов работы является отношение усреднённого времени выполнения миссии к эталонному усреднённому времени, рассчитанное по серии не менее чем из 10 запусков.

| Отношение T_avg / T_optimal_avg | Оценка |
|---|---|
| ≤ 1,05 | Отлично |
| 1,05 < δT ≤ 1,20 | Хорошо |
| 1,20 < δT ≤ 1,50 | Удовлетворительно |
| δT > 1,50 | Неудовлетворительно |

Дополнительные критерии:

- корректность расчёта оптимальной высоты полёта (соответствие условию `p_detected ≥ p_min`);
- надёжность обнаружения маркера (отсутствие ложноположительных и ложноотрицательных срабатываний во всех запусках серии);
- полнота покрытия области (отсутствие непросмотренных участков);
- стабильность результатов по серии запусков (низкое значение среднеквадратичного отклонения `σ_T`);
- качество исходного кода (структурированность, наличие комментариев, обработка исключительных ситуаций);
- полнота и научная обоснованность отчёта о проделанной работе.

При непревышении заданной максимальной высоты, но отсутствии обнаружения маркера хотя бы в одном запуске серии работа считается невыполненной независимо от достигнутого времени миссии.

7. Какие факторы могут привести к расхождению расчётной и фактически наблюдаемой высоты полёта в среде Gazebo?

## Результат проекта

Результатом проекта является алгоритм автономного поиска ArUco-маркера в заданной области с расчётом оптимальной высоты полёта на основе параметров камеры и размера маркера.

В ходе эксперимента должны быть получены:

- лог полёта квадрокоптера и событий детектирования;
- график маршрута с отмеченными зонами охвата камеры и положением обнаруженного маркера;
- расчётные выкладки по выбору рабочей высоты;
- таблица сравнения фактического времени миссии с эталонным;
- вывод о влиянии выбранной высоты полёта на эффективность поиска.

## Вывод

Эффективность автономного поиска визуальной метки в заданной области определяется балансом между площадью охвата камеры и размером маркера в пикселях изображения. Полёт на низкой высоте обеспечивает надёжное распознавание, но требует большого количества проходов и существенно увеличивает время миссии. Полёт на высоте, превышающей предельное значение `h_max`, приводит к пропуску маркера из-за недостаточной разрешающей способности.

Оптимальной является рабочая высота, незначительно меньшая `h_max`. При таком выборе достигается максимальная площадь охвата при сохранении надёжности детектирования. Применение маршрута типа «змейка» с перекрытием соседних проходов обеспечивает полное покрытие заданной области.

Поскольку положение маркера задаётся случайным образом, оценка качества алгоритма проводится по серии запусков с усреднением полученного времени. Такой подход позволяет исключить влияние конкретного расположения маркера на итоговую оценку и получить устойчивую характеристику разработанного решения.

Ожидается, что разработанный алгоритм обеспечит выполнение миссии с отклонением усреднённого времени от эталонного значения не более 5–20% при условии корректного расчёта рабочей высоты и построения траектории облёта.
